## Conclusions

1. Plan section 3.3 says `config.py` reads the data root "from an env var or the Colab default", but the stage prompt says only `colab.py` may know about Colab. ## Found during refactor (not fixed)

- **SAM bbox is one pixel short.** It stores `w = right - left`, so crops without padding lose the last row and column of the mask. The default 5% padding hides this for corals wider than 20 px. `masked_square_crop` has no padding, so the DINO masked-square crops lose that row and column. Negligible, and documented by a test.
- **A black photo pixel inside the mask counts as not visible.** `visible` is `any(crop != bg)`, so very dark pixels shrink `visible_px` and can push a small crop under `min_visible`. It matters only for crops near 500 px.
- **Masked-crop sharpness also measures the mask outline.** The coral-to-black edge adds Laplacian variance, so a flat but sharply outlined mask can pass the threshold. This is already item 8 of the plan. A flat crop with no outline measures 0.
- **Legacy `is_sharp_enough` defaults to 50.** The pipeline passes 80. The new function has no default.
- **`stage1_reason`, `reject_reason` and similar columns come back as NaN or None.** It depends on the pandas version (pandas 3 string columns use NaN). Use `isna()`, never `is None`.
- **OpenCV applies EXIF orientation in `imread`.** CM 8 computed the frame from the loaded image. `load_in_mask_frame` uses the same call, so frames stay consistent as long as OpenCV does the same, but the frame audit (`audit_json_dir`) is where any oddity would show.
- **Colab ships `opencv-python`, and `pip install -e .` adds `opencv-python-headless`.** Two OpenCV distributions share one `cv2` folder. It usually works. If parity or imports misbehave on Colab, restart the runtime or pin `opencv-python-headless<5`.
- **Ruff 0.17 also formats Markdown files.** `ruff format --check .` reformats python code blocks in `.md` files, so keep them valid (use `bash` fences for shell).
