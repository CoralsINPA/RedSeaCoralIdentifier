## Conclusions

- **Stage B code is complete.** What remains is real-data work: the user runs the baseline (about 25 minutes on a T4), then the portrait-impact and Millepora cells.
- **A portrait row in the expert set is not comparable.** Assaf judged crops cut by the legacy code. The reports therefore show landscape rows (the fair comparison with the legacy result) and portrait rows (informational) apart, and the portrait-impact report lists every portrait row.
- **The Millepora audit's portrait rows are not reused.** Every audit row on a portrait photo is put in the new blind sheet again. Landscape yes / no judgments are kept as they are and used as fully reviewed groups in the estimates; the old unsure crops are re-reviewed.

## Spec conflicts and deviations

1. **Extra modules:** `orientation`, `parity_manifest`, `parity_expert` (to keep `parity.py` near 300 lines), `baseline`, `reports`, `portrait_impact`, `genus_audit`, `review_scoring`, `review_export`, `viz`. The plan had a single `labeling.py`; the blind-review code is split out because it is a different job. `review_scoring.py` is 323 lines.
2. **`viz.py` started in Stage B** with `crop_grid_pdf` only, because a review sheet is useless without pictures. Stage C adds the rest.
3. **`labeling.py` has no tier logic** (the plan says "only if trivial"; the 20-genus workflow does not need it).
4. **Notebook setup cell:** the same logic as the parity notebook (clone with submodules, `pip install -e`, the editable-install import fix, `CORALID_DATA_ROOT`, restart detection), written without function definitions, with imports first (ruff E402) and `import coralid  # noqa: E402`. Versions are read with `metadata.distributions()`. 03 installs `[clip,viz]`, 04 installs `[viz]`.
5. **Baseline runtime:** about 25 minutes (0.8 s per image, Check B's rate), as the orchestrator said, not the "about 2 hours" in the stage text.
6. **`run_baseline` writes the two files itself** (atomic parquet, `save_embeddings`) after checking the merged parts, not through `ResumableRun.merge(paths)`, so a mismatch is found before anything exists. Rows are saved in manifest order.
7. **Check A4** is now PASS / FAIL against the recorded frame sizes (it was INFO), and **Check D4** (the 16 / 2 split) is INFO because it is unconfirmed.
8. **Blind sheet design choices** (the spec leaves them open): a simple random sample of each group; landscape crops judged yes / no before are excluded and their old answers are used in the estimates as fully reviewed groups; every portrait row of the old audit is re-reviewed, whatever it was judged; the expert's 40 crops are the old unsure crops plus a uniform random fill from the sheet; the hidden key is written to `reviews/keys/`, apart from `reviews/exports/`; the PDF caption is `#row key`. Defaults: 150 + 150 crops, 40 for Assaf, seed 0.
9. **`matplotlib` joined the `dev` extra** (the PDF test), and `[project.scripts]` gained `coralid`.
10. **`run_zero_shot` still supports masked crops only.** The A2 note tied bbox crops to this stage; the `sharpness_crop` option does not need them, so only the error message changed.

## Found during refactor (not fixed)

- **pandas 3 + pyarrow cannot merge two empty arrow-backed string columns** ("cannot construct ChunkedArray from empty vector"). Fixed where it bit (`normalize_keys` returns an object `image_name`), but any new code that merges possibly empty tables needs the same care.
- **`ResumableRun` parts are in the order images were finished**, so a resumed run merges in a different order. `run_baseline` sorts into manifest order; other users of `merge()` should not assume order.
- **Check A4 and Check C1 are tied to this dataset** (1,714 files, 44,211 masks). Fine for the parity notebook, wrong for any other data.
- **The old audit's `actual_genus`** may be empty for many "no" rows; `load_legacy_audit` will warn about each missing one.
- **The Drive file names for the bbox DINOv2 CSV disagree** between the plan (`coral_dino_encodings.csv`) and the CLAUDE.md Drive map (`coral_dinoV2_encodings.csv`, 181 MB). Confirm before deleting; never delete `coral_dinoV2_encodings_MASKS.csv` (the masked features are good).
- **Millepora Wilson intervals are not corrected for the analyst's bias.** They measure the analyst's answers, not the truth, until the agreement with Assaf is known.
