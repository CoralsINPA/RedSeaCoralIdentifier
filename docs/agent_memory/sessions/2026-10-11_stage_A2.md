## Spec conflicts and deviations

1. **Extra modules.** The spec lists no `parity.py`, `parity_report.py` or `predictions.py`. The first two exist because "the notebook's comparison logic is unit-tested in the package". `predictions.py` holds `compare_predictions`, `load_legacy_predictions` and `distribution_vs_ground_truth` so that `evaluation.py` stays under about 300 lines; `evaluation` re-exports them, so the specified API is unchanged.
2. **Soft corals are not a label set.** The 4 soft genera are a top-level `soft_genera` list in `genera.yaml`, plus the `soft4_taxonomy` prompt set. A label set named `soft4` could be picked by mistake. They are used only to recognise expert labels and V2 columns as "known, outside the label set".
3. **Encoder interface.** `encode_images` accepts a list of `preprocess` outputs or a stacked tensor (the spec says `batch_tensor`), so `zero_shot` needs no torch. Encoders return **unnormalized** float32 numpy arrays; `zero_shot` normalizes.
4. **`run_zero_shot` signature.** It takes the image manifest and uses its `keep` column ("the existing keep decision"), plus optional `run` (a `ResumableRun`), `keep_embeddings`, `group_size` (default 32 images encoded together) and `max_consecutive_failures` (default 5). Masked crops only: `crops.mode == "bbox"` raises `NotImplementedError` until the Stage B `sharpness_crop` option, because the manifest's keep decision is based on the masked crop.
5. **`common` as a prompt format.** The spec lists it; the legacy code had no stand-alone `common` format. It uses the `common` set alone.
6. **`ResumableRun` for the manifest.** Keys are image names. `image_manifest(run=...)` finds the JSON file of a done image with `json_name_for` (stem plus `.json`, which `audit_json_dir` verifies). If a JSON cannot be read at all, its failure is logged under the JSON file name, because the image name is inside the JSON.
7. **Check order and Check D.** Check D (new, from the session rules) runs before Check C so that the quick checks come first. The summary handles a skipped check (`NOT RUN`, overall `PARTIAL`).
8. **The legacy cell** drops legacy section 10 (the confidence histogram) because it saves a PNG into the run folder over an existing file (the PNG exists, see above), and keeps `final_df` in memory instead of writing the CSV. Both are in the cell's list of adaptations, with the paths and `df_counts`.
9. **Ruff skips the parity notebook** (`extend-exclude` plus `force-exclude`), because ruff 0.17 lints and formats notebooks and its formatting would change the verbatim legacy text. The notebook's own cells were formatted with ruff when it was generated.
10. **Small API changes.** `masks.as_int` is now public (it was `_as_int`). `manifest.write_manifest` has `overwrite`, `geometric_manifest` has `timings`, `image_manifest` has `run`. Defaults keep the A1 behavior.
11. **Notebook cell ids** are `0`, `1`, ... because nbstripout rewrites them that way; this keeps the file stable under the pre-commit hook.

## Found during refactor (not fixed)

- **Running WC cell 14 overwrites Drive files.** It rewrites `coral_weak_labels_<model>_<prompt>_<mode>_<sample>.csv` and `confidence_dist_<model>_<prompt>.png` in the run folder each time, without asking. Someone did this on 2026-10-11. The parity notebook's legacy cell has both writes removed.
- **`configs/` is not part of the installed package.** `genera.load_genera()` finds `configs/genera.yaml` through the clone (`pip install -e`), and raises a clear error otherwise. A plain `pip install git+https://...` (plan section 3.3, `colab.py`) would not contain it. Stage C must either ship the YAML as package data or clone the repo. Not decided here.
- **A fresh editable install is not importable until its `.pth` is read** (see above). Stage C's `colab.setup()` needs the same fix.
- **Masked-crop sharpness passes flat photos.** In the dry run, photos with a flat grey content still passed `Laplacian variance >= 80` because the grey-to-black mask outline is a strong edge, so no crop was rejected as blurry. This is the known plan item 8, now seen in a run.
- **ruff 0.17 lints and formats `.ipynb` files**, besides the `.md` files noted in A1. Stage C's five notebooks will be checked by `ruff check` and `ruff format --check`, so write them accordingly.
- **The A1 note about OpenCV is now handled** by the `<5` pin, and the setup cell warns if `opencv-python` and `opencv-python-headless` differ in version.
- **`expert_set` wording is unverified** (above), and the older open question remains: how `MISSING_LABEL` rows are counted. `evaluate` reports `missing` as its own status, so Check D shows it.
