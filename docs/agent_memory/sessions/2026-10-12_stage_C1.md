## Spec conflicts and deviations

1. **`_atomic` has no "exclusive-create helpers"** (the prompt says to use them if they exist); `atomic_write_text_exclusive` is new.
2. **`segment` uses JSON existence as its done marker**, not `ResumableRun.add`. The run object is used for the failure log only. A failure is "unresolved" while its image has no JSON.
3. **`embed` runs over the manifest's `keep` rows** with the masked square crop, not over all 44,211 masks like CM cell 9 (or its own filters, like cell 11): "filter once". Features are raw, as in the legacy CSVs, and the file is named `<model>__masked_square.npz` because the crop differs from the baseline's `masked`. It refuses CLIP-family names so that it cannot create the baseline's `finetuned-bioclip__masked.npz` without its predictions.
4. **Extra modules:** `embed.py`, `jobs.py`. `write_probe_report` is in `reports.py` and `train_probe` in `jobs.py`, so that `probe.py` (297 lines) does not depend on the config. `segmentation.py` (364), `cli.py` (364) and `config.py` (364) are above the 300-line guide (help texts, docstrings, dataclasses).
5. **Plan §3.3 lists a `tier` command.** The prompt's command list has none (V2's tiers are not carried forward), so there is none.
6. **`export-review`, `evaluate`, `build-manifest`** are wrappers over notebook cells (04 cell 9, 03 cells 6 and 9, parity Check C); `build-manifest --geometric` is an addition.
7. **`build-manifest` refuses to reuse a manifest** whose saved filter or crop settings differ from the config (keys missing from an older meta are ignored), instead of loading it silently.
8. **Plan decision 5.4** (plain `pip install git+https://...`) is superseded by the prompt: clone with submodules and `pip install -e`.
9. **DINOv2 comes from `torch.hub.load('facebookresearch/dinov2', 'dinov2_vits14')`, unpinned**, as in the legacy cell. The sandbox could not download it (HTTP 400 from the proxy), so the real DINO weights have never been loaded; the encoders are tested with tiny stand-in models.

## Found during refactor (not fixed)

- **CoralSCOP's `build_sam` has no `map_location`** (`torch.load(f)`), so a CPU-only machine cannot load a checkpoint saved on a GPU; segmentation needs a GPU runtime anyway. It also returns an untrained model if the checkpoint path is neither a file nor a folder, which `build_generator` guards against.
- **Importing the submodule writes `__pycache__` into `third_party/CoralSCOP`** and makes it show as modified in `git status`. `PYTHONDONTWRITEBYTECODE=1` avoids it; the files this session created were deleted.
- **Whether CoralSCOP's generator can raise instead of returning `[]` for a photo with no masks is not known.** The legacy cell's comment mentions an `IndexError`. The real data has no JSON with a `note` (parity Check A5), so it has not happened in 1,714 photos. If it does, the photo sits in the failure log and the job reports it; accepting it as empty needs a decision.
- **`ResumableRun.unresolved_failures()` lists a failure until its image is in the done-set.** For `image_manifest` a malformed JSON is logged under the JSON's file name, not the image name, so it can never resolve itself (pre-existing; a test relies on it).
- **`list_mask_files` lists any name ending in `.json`**, dotfiles included. A crash inside the older `atomic_path` writer can leave `.<stem>.tmp<pid>.json` in a folder. The new exclusive writer names its temp file without `.json`.
- **`viz.cut_crops` holds every thumbnail in memory** (about 0.8 MB each at 512 px); sample before drawing thousands.
